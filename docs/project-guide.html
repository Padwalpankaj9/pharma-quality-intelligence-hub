1. What This Project Is

An end-to-end FAIR Pharma Quality Data Product, Custom Python MCP v2 Server, RBAC-Gated FastAPI Service, and Evaluated Quality Investigation Agent built on live public FDA Drug Enforcement (Recall) data and deployed to Databricks Unity Catalog (workspace.pharma_quality_fair).

4. Interview Q&A Cheat Sheet

  1. Why both SQLite and Databricks Unity Catalog? Read-only SQLite keeps local dev, MCP tests, and GitHub Actions CI sub-second with zero cloud secrets, while Unity Catalog proves live Delta governance (SET TAGS, CHECK, PK).
  2. Why Unity Catalog SET TAGS in addition to TBLPROPERTIES? Unity Catalog tags power Workspace Search, schema-to-table inheritance, and ABAC (FAIR Findable + Accessible), whereas TBLPROPERTIES holds table metadata.
  3. Why measure Guardrail False Positive Rate (FPR)? Naive filters block real pharma phrases like “drop in potency” or “union of trends”. Measuring 100% security recall with 0% FPR proves production safety.
  4. Why enforce RBAC inside the agent and MCP server? Per OWASP Agentic Top 10 (ASI03), API-edge auth is not enough; enforcing is_mcp_tool_allowed at the tool layer guarantees least privilege across REST, agent, and stdio MCP.
  5. How is MCP tested? Using MCP SDK v2’s in-memory Client(mcp_server.mcp) to test real protocol framing (list_tools annotations/schemas, call_tool structured_content, RBAC denial, and fair:// resources).
  6. What real bug did your evals catch? The ZERO-01 case (“Class III nitrosamine recalls”) caught a substring bug where class ii matched inside class iii before class iii was checked.
